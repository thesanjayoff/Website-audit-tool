Missing Content-Security-Policy header

affects 2 pages

No Content-Security-Policy header was found on either page audited.

Why it matters: Without a CSP, the browser has no extra protection against injected scripts beyond the page's own code.

Suggested fix: Add a Content-Security-Policy header, starting in report-only mode to avoid breaking the site.

Effort: low · Impact: high · Engine: header-check

medium

Form elements must have labels

affects 1 page

The contact form's phone number field has no associated <label>, aria-label, or aria-labelledby.

Why it matters: Screen reader users may not understand what the field is for, which can mean a lost lead.

Suggested fix: Add <label for="phone">Phone number</label> immediately before the field.

Effort: low · Impact: high · Engine: axe-core · WCAG: 4.1.2

medium

Hero image is not served in a modern format

affects 1 page

The homepage's hero image is a large PNG; converting it to WebP/AVIF would cut its size significantly.

Why it matters: Slower image loads push back Largest Contentful Paint, which can hurt both conversions and Core Web Vitals-linked search signals.

Suggested fix: Re-export the hero image as WebP (with a JPEG fallback) and serve it via <picture> or a modern image CDN.

Effort: low · Impact: medium · Engine: lighthouse

  • https://riverside-dental.demo.invalid/
    ~340KB potential savings
medium

Missing meta description

affects 1 page

The contact page has no meta description, so search engines will auto-generate a snippet.

Why it matters: An auto-generated snippet is less persuasive than a written one and can hurt click-through from search results.

Suggested fix: Add a unique, ~150-character meta description summarizing what visitors can do on this page.

Effort: low · Impact: medium · Engine: seo-checks

  • https://riverside-dental.demo.invalid/contact

8 tap targets smaller than the recommended 24x24px minimum

Why it matters: Visitors on mobile may mis-tap small controls, which is a small but real conversion drag.

Suggested fix: Increase tap target size to at least 24x24 CSS pixels with adequate spacing.

Methodology & limitations

This is not a penetration test, a full vulnerability assessment, or an accessibility compliance certification. It combines automated lab measurements and rule-based checks with plain-English explanations. Automated accessibility tools only catch roughly 30-50% of real WCAG issues — see the manual checklist below.
  • Lighthouse 13.6.0 — performance/SEO/best-practices lab scores, median of multiple runs per page.
  • axe-core 4.14.1 and HTML CodeSniffer via Pa11y 10.0.0 — automated WCAG 2.0/2.1/2.2 A/AA checks.
  • Core Web Vitals lab thresholds: LCP good ≤ 2500ms, CLS good ≤ 0.1, INP good ≤ 200ms (Lighthouse cannot measure INP directly in the lab; Total Blocking Time is shown as a labelled proxy).
  • Overall score = weighted average of Performance (30%), SEO (25%), Accessibility (25%), Security (20%). Full formula and weights are documented in the tool's source (src/server/config/scoring.ts) and are adjustable.
  • Accessibility results combine axe-core and HTML CodeSniffer (via Pa11y) automated rule checks against WCAG 2.0/2.1/2.2 A and AA, plus a handful of extra heuristic checks (lang attribute, heading order, skip links, form labels, vague link text, focus-outline suppression). Automated tools are estimated to catch roughly 30-50% of real WCAG failures. They cannot assess whether content actually makes sense to a screen reader user, whether custom widgets behave correctly with assistive tech, or many other judgment-based criteria. This report is not a substitute for manual testing and must never be used to claim a site is "WCAG compliant" or "ADA compliant" — only that these specific automated checks passed or failed.
  • When enabled, the optional AI layer only rewrites the wording of the executive summary and finding explanations for a non-technical audience. It is given only computed scores and finding titles/severities/business impact — never raw page content, headers, or cookies — and cannot change any score or add/remove findings. AI-written text is labelled below and can always be edited.

Manual accessibility checklist (not automatable)

  • Navigate the entire page using only the keyboard (Tab, Shift+Tab, Enter, Space, arrow keys) — can you reach and operate everything?
  • Run through the key user flows with a screen reader (NVDA/JAWS on Windows, VoiceOver on Mac/iOS, TalkBack on Android).
  • Zoom the page to 200% and reflow at a narrow viewport — does content remain usable without horizontal scrolling or overlap?
  • Check that any video has accurate captions and any audio-only content has a transcript.
  • Verify color is never the only way information is conveyed (e.g. error states, required fields, chart legends).
  • Test forms end-to-end for clear error messages that are announced to assistive technology.
